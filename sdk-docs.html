Docs — Python SDK 0.2.0

Decisions, typed.

The fronesa package wraps the decision API in typed Python: one Client, one Decision dataclass, and an exception hierarchy that tells you exactly what went wrong. Retries, timeouts, and connection pooling are built in.

1 — Installation

From source today.

Requires Python 3.9+. The package is built and tested; until it lands on PyPI, install it from source:

bash — install from source
$ git clone https://github.com/suretyai/fronesa.git
$ cd fronesa/sdk/python
$ pip install .
PyPI: coming soon. pip install fronesa is reserved and will work once the package is published — until then, do not use it; it will fail. This page will be updated the day it goes live.
2 — Quickstart

Three lines to a decision.

Get a key first — email surety.ai@proton.me and we will issue one. Keys are sent as Authorization: Bearer; store yours in an environment variable, never in code.

python — quickstart
from fronesa import Client

client = Client(api_key="sk-...")
result = client.decide("Free prizes, claim now!")
print(result.decision, result.confidence, result.escalated)
The escalation contract: when result.escalated is True, the model is telling you it is not confident enough to decide. Do not auto-act — route the item to human review. The result.requires_review property is an alias for escalated, for code that reads better at the call site.
Cold starts — read this before your first call: the free tier sleeps after ~15 idle minutes, and the first request after idle can take up to ~90 s while the container boots. The default timeout=10.0 will not survive a cold start — the request raises RequestTimeoutError, which is not retried. Two honest options: allow a long first call with Client(api_key=..., timeout=(10.0, 120.0)) (fail fast on unreachable hosts, tolerate the boot), or pre-warm the service with an unauthenticated GET /health before your first decide().
3 — API reference

Everything the package exports.

Import from the top level: from fronesa import Client, Decision, APIError, .... Two classes, eight exceptions — nothing else.

Client

Client(api_key, base_url=..., timeout=..., max_retries=..., backoff_base=..., backoff_max=..., pool_connections=..., pool_maxsize=...). Constructor arguments:

ParameterMeaning
api_keyRequired. Your Fronesa API key, sent as Authorization: Bearer. Empty or missing raises ValueError immediately — no request is made.
base_urlAPI base URL. Default https://fronsea-api.onrender.com. A trailing slash is stripped for you.
timeoutPer-request timeout: a float in seconds, or a (connect, read) tuple, e.g. timeout=(3.0, 15.0) to fail fast on unreachable hosts while allowing slow responses. Default 10.0. Must be positive — anything else raises ValueError. Cold-start warning: the free tier's first request after ~15 idle minutes can take up to ~90 s, which exceeds the 10 s default — use timeout=(10.0, 120.0) or pre-warm with GET /health (see Quickstart).
max_retriesRetries on 429 and 5xx with exponential backoff + jitter (default 3). 0 disables retries. Negative raises ValueError.
backoff_baseBase backoff in seconds; attempt n waits roughly backoff_base × 2**n before jitter (default 1.0). Must be positive.
backoff_maxUpper bound for any single backoff sleep, including a server-sent Retry-After (default 30.0). Protects against a mistaken or malicious huge Retry-After header. Must be positive.
pool_connectionsNumber of connection pools cached by the underlying session (default 10).
pool_maxsizeMax connections per pool — raise for threaded workloads (default 10).

Client.decide(text)

Posts to POST /decide and returns a Decision. text must be a non-empty string — an empty string raises ValueError locally without touching the network. If the server's response is malformed (missing fields, wrong types), the client raises APIError instead of handing you a half-built object.

Client.health()

Calls GET /health and returns the response payload as a dict. No API key needed — useful for uptime checks and smoke tests.

Decision

A frozen dataclass — one typed answer. Fields:

FieldMeaning
decisionThe model's answer — a label string (e.g. spam / ham).
confidenceModel confidence, a float in [0, 1] — well-calibrated on SMS-style inputs. 0.78 means the model assigns 78% probability to its answer.
escalatedThe honest flag. True means the model is not confident enough to decide — do not auto-act; route to human review.
versionModel version that answered. Log it so you can compare behavior across versions.

Decision.requires_review is a read-only property, an exact alias for escalated — True means the item needs a human, never automatic action.

4 — Error handling

One hierarchy, exact meanings.

Every failure from the client is an APIError. Catch the base class for “anything went wrong”, or catch a subclass for precise handling. Two validation errors are plain ValueError — raised before any network call, so they are never APIErrors.

APIError                  base class — catch this for "any API failure"
├── AuthError             401 / 403 — bad or missing API key
├── RateLimitError        429s kept coming after all retries
│   └── .retry_after  the server's last Retry-After hint (seconds), or None
├── ServerError           5xx kept coming after all retries
├── BadRequestError       400 — the request itself was rejected
└── NetworkError          connection / DNS / TLS failures
    └── RequestTimeoutError  the request exceeded your timeout
SituationRaised
401 or 403 from the APIAuthError — check the key in FRONESA_KEY.
429 persists after all retriesRateLimitError — read .retry_after for the server's hint.
5xx persists after all retriesServerError — our fault; report it with the details in the message.
400 (missing/invalid text)BadRequestError — the message carries the server's explanation.
Connection refused, DNS, TLSNetworkError.
Request exceeds timeoutRequestTimeoutError (a NetworkError, so existing except NetworkError blocks still catch it).
Unexpected status codeAPIError with the status and body in the message.
Malformed /decide responseAPIError — the raw payload is included for diagnosis.
Empty api_key / empty text / invalid timeout or retry configValueError — raised locally, before any request. Not an APIError.
python — handling errors
from fronesa import Client, APIError, AuthError, RateLimitError

client = Client(api_key="sk-...")
try:
    result = client.decide(text)
except AuthError:
    raise SystemExit("bad API key — check FRONESA_KEY")
except RateLimitError as e:
    wait = e.retry_after or 60
    # back off and try again later
except APIError as e:
    log("decision failed", error=str(e))
5 — Rate limits and retries

100 a minute, politely.

Each key gets 100 requests per minute. The client handles 429s for you: it retries with exponential backoff and full jitter, honors the server's Retry-After header (capped at backoff_max), and only raises RateLimitError when every retry is exhausted. 5xx responses get the same treatment and become ServerError if they persist.

KnobDefaultEffect
max_retries3Retries on 429 and 5xx. Set to 0 to disable retries entirely — the first 429 then raises RateLimitError immediately.
backoff_base1.0sAttempt n waits roughly backoff_base × 2**n (1s, 2s, 4s …) before jitter.
backoff_max30.0sNo single wait ever exceeds this — including a server-sent Retry-After.
Jitter is full, not decorative. Each wait is uniform(0, wait), so a fleet of clients hitting the limit does not retry in lockstep and stampede the server. If you raise pool_maxsize for threaded workloads, keep max_retries at its default — the backoff is per request, and a stampede of threads each retrying aggressively is how keys get reviewed.

Timeouts are enforced per request by timeout (default 10s, or a (connect, read) tuple). A timed-out request raises RequestTimeoutError — it is not retried, because the server may already be working on it. A cold start (first request after ~15 idle minutes, up to ~90 s) therefore raises RequestTimeoutError at the 10 s default — it does not get retried, so the call fails instead of waiting out the boot. Plan for it: timeout=(10.0, 120.0) or pre-warm via GET /health.
