Fronesa — legal

Developer terms, in plain language.

The rules for building on the Fronesa decision API. These sit alongside the pilot terms, privacy policy, and data handling page — together they are the whole agreement.

LAST UPDATED — OCTOBER 2026

1. Your license to use the API

We grant you a non-exclusive, non-transferable, revocable license to call the Fronesa API with the key we issue you, and to build the results into your own product or internal tooling.

  • Your key is yours alone. Don’t share it, don’t embed it in client-side code where anyone can read it, and don’t post it in public places (we’ve seen this happen — it ends with the key being revoked).
  • If a key is exposed, tell us at surety.ai@proton.me and we’ll rotate it. You are responsible for traffic sent with your key until it’s revoked.
  • You may not resell raw API access or present Fronesa’s decisions as your own model’s output.

2. Acceptable use

Use the API for decisions, not deception. You agree not to:

  • Use it to generate spam, phishing, fraud, or abusive content — we classify that material; we don’t help produce it.
  • Send illegal content, or use decisions to break the law.
  • Probe, scrape, or reverse-engineer the API to extract the underlying model or training data — bulk harvesting of decision pairs to clone the model counts as abuse.
  • Circumvent rate limits by rotating keys, spoofing identity, or distributing load to evade the per-key cap.
  • Run the API on high-stakes outcomes — medical, legal, credit, employment, or safety-critical decisions — without meaningful human review of each decision that matters. Our confidence scores are a guide, not a verdict.
Escalation is a feature, not a failure. When the API returns escalated: true, it is telling you it isn’t sure. Routing escalated items to a human is the correct way to use us — ignoring the flag and auto-acting on low-confidence decisions is not.

3. Rate limits & fair use

Current limits, enforced per API key:

  • 100 requests per minute per key. Over the limit you get HTTP 429 with a Retry-After header — back off and retry.
  • 64 KB maximum request body on /decide. Larger bodies are rejected.
  • Batch endpoints, if offered, count each item against your per-key limit — a 50-item batch is 50 requests.

These are pilot limits and may change as the service grows. If your legitimate use needs more headroom, write to us — we’d rather raise your limit than have you work around it.

4. Uptime & support — best effort

The pilot API runs on best effort. There is no SLA: no promised uptime percentage, no guaranteed latency, no support response-time commitment.

We may throttle, pause, or change the service — including model versions behind /decide — with or without notice. The version field in every response tells you which model answered, so you can detect changes on your side.

Measured latency and benchmark figures on this site are lab measurements, not guarantees — see the pilot terms.

5. Your data through the API

Retention, isolation, deletion, and our no-training-without-consent rule are covered on the data handling page, which forms part of these terms. In short: we process what you send to return decisions, we don’t sell it, and we don’t train shared models on it without your written consent.

6. Liability, honestly limited

The API is provided “as is,” without warranties of any kind — including accuracy, reliability, or fitness for a particular purpose. A wrong decision is possible on any request; that’s what the confidence score and the escalation flag are for.

To the extent permitted by law, we are not liable for indirect, incidental, or consequential damages — lost profits, lost data, or actions you took on our decisions. 7. Suspension & termination

You can stop using the API at any time — just stop calling it, and ask us to delete your key.

We may suspend or revoke a key at any time, including for abuse, terms violations, or changes to the pilot program. When we reasonably can, we’ll tell you why before or shortly after — but for active abuse (spam generation, model extraction, attacks on the service) we’ll act first and explain after.
