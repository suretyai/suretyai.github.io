Integration guide

Support ticket triage

Keep spam out of your support queue automatically. Spam tickets close themselves; real tickets reach agents faster — with the uncertain ones flagged, never auto-closed.

The problem

Support inboxes drown in SEO pitches, phishing, and bot-submitted junk. Every spam ticket an agent opens is a minute stolen from a real customer. You don't need a smarter router — you need the junk gone before triage starts.

What this guide is — and isn't: this is spam filtering for the ticket queue, not topic routing. The production model classifies spam vs. legitimate text; it does not sort tickets into billing/technical/sales. If a vendor promises full auto-routing, ask what their false-positive rate is on real customer tickets.

The code

triage.py26 lines
import os
from flask import Flask, request, jsonify
from fronesa import Client, APIError

app = Flask(__name__)
fronesa = Client(api_key=os.environ["FRONESA_API_KEY"])

@app.post("/tickets/incoming")
def incoming():
    body = request.json or {}
    text = f"{body.get('subject', '')}\n{body.get('body', '')}".strip()
    if not text:
        return jsonify({"action": "route", "queue": "general"}), 400
    try:
        result = fronesa.decide(text)
    except APIError:
        # API down: route to agents, never drop a ticket.
        return jsonify({"action": "route", "queue": "general",
                        "note": "fronesa_unreachable"})
    if result.decision == "spam" and not result.escalated:
        return jsonify({"action": "close_as_spam"})
    tag = "needs_review" if result.escalated else None
    return jsonify({"action": "route", "queue": "general", "tag": tag,
                    "confidence": result.confidence})

app.run(port=8000)
Why only confident spam auto-closes: closing a real customer's ticket as spam is the most expensive mistake in support. The lab-measured zero false positives on spam make confident closes safe; anything uncertain gets a human. Your agents see a needs_review tag and a confidence score — not a black box.

What escalation looks like here

API saysService returnsWhat happens
spam, confident{"action":"close_as_spam"}Ticket auto-closed, logged — agent never sees it
ham, confident{"action":"route"}Normal queue, no tag
escalated{"action":"route","tag":"needs_review"}Agent sees it with the score — prioritizes the review

Agents' decisions on needs_review tickets — real spam they close, real customers they help — are the feedback the learning loop retrains on. The filter gets better at your spam, not generic spam.

Honest scope: this guide filters spam/scam text — that's what the production model is trained for (lab accuracy 0.9875 on spam vs. legitimate messages). It does not detect angry customers, urgent tickets, or VIPs. Don't promise your support team coverage it doesn't have.

SDK reference: Client(api_key, ...) · client.decide(text) → Decision(decision, confidence, escalated, version) · exceptions: APIError and subclasses.
