Integration guide

Forum & comment moderation

Hold spam comments for review before they ever publish. One generic webhook endpoint that Discourse, a custom forum, or any CMS can call.

The problem

Comment spam — SEO link dumps, crypto pitches, fake support numbers — poisons forums and blogs. CAPTCHAs annoy real users and don't stop much. You want spam held before it publishes, without a human reading every comment.

How it fits together

Your platform POSTs the comment text to /comments/moderate before saving it. The endpoint returns an action your platform already understands: publish it, or hold it in the moderation queue.

The code

moderate.py23 lines
import os
from flask import Flask, request, jsonify
from fronesa import Client, APIError

app = Flask(__name__)
fronesa = Client(api_key=os.environ["FRONESA_API_KEY"])

@app.post("/comments/moderate")
def moderate():
    text = (request.json or {}).get("text", "")
    if not text.strip():
        return jsonify({"action": "reject", "reason": "empty"}), 400
    try:
        result = fronesa.decide(text)
    except APIError:
        # Fail open: publish, but flag for later review.
        return jsonify({"action": "publish", "flagged": True})
    if result.escalated or result.decision == "spam":
        return jsonify({"action": "hold", "confidence": result.confidence})
    return jsonify({"action": "publish"})

app.run(port=8000)
Why fail open? If the API is unreachable, blocking all comments punishes your real users for our outage. Publishing with a flag keeps the forum usable; your mods sweep flagged comments later. For high-risk contexts (children's sites, finance), fail closed instead — hold everything until the API answers.

What escalation looks like here

API saysEndpoint returnsYour platform
spam, confident{"action":"hold"}Comment sits in the mod queue, never visible
ham, confident{"action":"publish"}Comment goes live immediately
escalated{"action":"hold"} + confidenceMod queue with the score shown — human approves or rejects

Escalated comments are the interesting ones: borderline phrasing, new spam patterns the model hasn't seen. Your mods' approve/reject clicks on these are exactly the feedback the learning loop is built to learn from.

Honest scope: this guide filters spam/scam text — that's what the production model is trained for (lab accuracy 0.9875 on spam vs. legitimate messages). It is not a toxicity or harassment detector. Don't promise your community coverage it doesn't have.
