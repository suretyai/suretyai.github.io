Docs — getting started

Your first decision
in five minutes.

One endpoint, one key, one honest contract: every answer carries a confidence and an escalation flag. No SDK to install yet — plain HTTPS is the whole integration.

Step 1 — Get an API key

Keys are issued by hand.

There is no self-serve signup yet. Email surety.ai@proton.me with what you want to decide on, and we will issue you a key. Early access is free; there is no SLA while we build toward paid plans.

Store it like a password. Put the key in an environment variable (FRONESA_KEY) or a secrets manager — never in client-side code, never in a public repo. If a key leaks, tell us and we will rotate it.
Step 2 — Make your first call

One POST, one answer.

Send the text you want judged to POST /decide. Replace $FRONESA_KEY with your key.

bash — your first decision
$ curl -X POST https://fronsea-api.onrender.com/decide \
  -H "Authorization: Bearer $FRONESA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "Free prizes, claim now!"}'
200 — what comes back
{
  "decision": "spam",
  "confidence": 0.78,
  "escalated": true,
  "latency_ms": 1.64,
  "version": "v1"
}

That is the whole contract. No polling, no callbacks, no sessions — one request in, one typed answer out.

Step 3 — Read the response

Five fields. No surprises.

FieldMeaning
decisionThe model's answer — a label from the model's vocabulary (e.g. spam / ham).
confidenceModel confidence, 0 to 1 — well-calibrated on SMS-style inputs. 0.78 means the model assigns 78% probability to its answer.
escalatedThe honest flag. true means the model is telling you it is not confident enough to decide. See Step 4.
latency_msServer-side time spent deciding, in milliseconds. Useful for your own latency budgets — but it measures only the model's decision time, not container boot: the first request after ~15 idle minutes can take up to ~90 seconds on the free tier, and that time will not appear in this field.
versionModel version that answered. It changes when the learning loop ships a better model; log it so you can compare.

Every response also carries an X-Request-ID header. Keep it — if anything looks wrong, send it to us and we can trace exactly what happened.

Step 4 — Handle escalations

When it says “I don't know,” listen.

escalated: true is not an error — it is the model doing its job. It means confidence fell below the model's threshold, so the answer is a guess you should not act on.

The rule: never auto-act on an escalated decision. Route it to a human reviewer (or a stronger model). Acting on an escalated decision as if it were confident defeats the purpose of the flag — it exists precisely so your system knows when to ask a person.

The pattern looks like this: confident decisions flow straight through; escalations land in a review queue. Every resolved escalation is a labeled example — the same examples the learning loop trains on next week, so your escalation rate should fall over time instead of compounding.

Step 5 — Rate limits and errors

100 a minute. Then wait.

Each key gets 100 requests per minute. Past that you get a 429 with a Retry-After header telling you how many seconds to wait. Back off, don't hammer — sustained 429s are how keys get reviewed.

StatusMeaning
400Malformed request — missing text, empty string, or not JSON. The body explains.
401Missing or invalid API key. Check the Authorization: Bearer header.
413Request body over the 64 KB cap. Shorten the text or split it.
429Rate limit exceeded. Honor Retry-After and retry.
500Our fault, not yours. Bodies never contain stack traces — send us the X-Request-ID.

Error bodies share one shape — {"error": "human-readable message", "code": "MACHINE_CODE", "request_id": "..."} — so one handler covers all of them. text must be 1 to 65,536 characters.

Step 6 — Python

Ten lines of requests.

No SDK to install yet — the Python SDK (pip install fronesa) is packaged but not published. Until then, requests is the integration.

python — decide.py
import os, time
import requests

API = "https://fronsea-api.onrender.com"
KEY = os.environ["FRONESA_KEY"]  # email surety.ai@proton.me for one

def decide(text):
    r = requests.post(
        f"{API}/decide",
        headers={"Authorization": f"Bearer {KEY}"},
        json={"text": text},
        timeout=10,
    )
    if r.status_code == 401:
        raise SystemExit("bad API key — check FRONESA_KEY")
    if r.status_code == 429:
        time.sleep(int(r.headers.get("Retry-After", 60)))
        return decide(text)  # one polite retry, then back off
    r.raise_for_status()
    return r.json()

out = decide("Free prizes, claim now!")
if out["escalated"]:
    send_to_human_review(out)   # your queue — never auto-act here
else:
    act_on(out["decision"], out["confidence"])
Two probes need no key at all. GET /health and GET /version are open — useful for uptime checks and for seeing which model version is currently serving.
